- 2026-10-09 · P3-D8 · **P-1.1 SEC-008 + QA N-1 (signed client IP, login limits).**
  - The Next.js server (NextAuth `authorize()` and `/api/proxy-pdf`) sends `X-CDC-Client-IP` + `X-CDC-Client-IP-Ts` + `X-CDC-Client-IP-Sig` = HMAC-SHA256(`ip|ts`, `INTERNAL_PROXY_SECRET`) via `lib/signedclientip.js` (Web Crypto, server-only env).
  - Laravel's global `TrustSignedClientIp` middleware (prepended, so throttles/logs/audits all see it) accepts it only with a valid signature and a timestamp within ±120 s, then sets `REMOTE_ADDR`; request attribute `client_ip_source` = `signed` | `direct` | `invalid_signature` (P0.4 reuses this for the login log's "flagged" IP). Empty secret = feature off.
  - The client IP comes from `X-Forwarded-For`, `CLIENT_IP_PROXY_HOPS` (default 1) entries from the right; Next.js only fills XFF when absent, so **production must run Next behind a reverse proxy that appends the real address** (handover item).
  - `POST /api/auth/login` left the 60/min `api` group: its own `login-ip` limiter, 600/min per client IP (owner: campus NAT). The F-016 hard 10/min-per-account lock is replaced by `LoginThrottleService`: 5 free failures per account+IP, then 1, 2, 4 … s after the last failure (cap 60 s); wrong passwords from ≥5 distinct IPs make every IP wait (cap 30 s); a correct password clears the account+IP counter; window 15 min; cache keys are hashes only. 429 carries `Retry-After` and "Too many attempts. Try again in N seconds."
  - `FixF016LoginThrottleTest` updated to the approved semantics (rotating IPs still throttled; no hard lockout). New `tests/Feature/Security/LoginThrottleTest` (7). - 2026-10-09 · P3-D9 · **P-1.2 Daily mail-recipient cap.**
  - Setting `mail_daily_recipient_cap` (Settings → Mail; default **1800**, 0 = no cap; admin-editable 0–100000, audited `setting.update`). 1800 leaves headroom under a typical 2,000/day mailbox; the owner sets the production mailbox's real limit.
  - `MailQuotaService::reserve(n)` books `n` recipients on the first IST day with room (table `mail_daily_usage`, row-locked inside a transaction) and returns null (send now) or 00:05 IST of that later day (UTC). Every address counts: each BCC student **and** the portal's own To address (so a bulk message of N students = N + 1).
  - `MailDispatchService`: `sendBulk` shrinks batches to at most cap − 1 BCC; `send` and `sendBulk` queue deferred mail with `Mail::later($when)` (also in Immediate/sync mode, so nothing is dropped; a queue worker is required). `email_logs.scheduled_for` (new column) records when a deferred mail is due.
  - Scope: mail sent through `MailDispatchService` (all student mail). Phase 1 transactional mails (password reset, company form notices, recruiter verification, alumni confirmation) are not counted: low volume, and they must not wait a day.
  - Settings API returns `mail_quota` {date, cap, used, remaining, deferred}; the Mail tab shows it next to the limit field.
  - Tests: `MailDailyCapTest` (6). Full gate 672 passed. UI check of the Mail tab is pending P-1.12 (the browser's admin session had an expired API token, SEC-015); API checked live with the demo admin.
