## (b) Findings, by severity

### Medium

**F1. A company can decide, or silently override, a job profile's Allowed Student Categories.**
- **Where:**
  - `backend/app/Http/Controllers/AdminPostingController.php:212-214` (open) and `:118-121` (preview) build the eligibility snapshot as `$this->snapshot($form) + array_filter(['allowedStudentCategories' => …admin choice…])`.
  - `snapshot()` (`:697-702`) copies every `JobPosting::SNAPSHOT_KEYS` key from the company-written `form_data`, and `allowedStudentCategories` is now one of those keys (`Models/JobPosting.php:19-23`).
  - Companies write `form_data` as free JSON (`app/Http/Requests/StoreJnfRequest.php:33`, `StoreInfRequest.php:33`: `'form_data' => ['nullable','json']`).
  - PHP's `+` keeps the left-hand key, so the company value wins.
- **Effect:**
  1. A JNF/INF carrying `"allowedStudentCategories":[id]` restricts eligibility even though the CDC chose no category.
  2. When the CDC picks categories in "Open for Applications", its choice is silently replaced by the company's.
  3. The eligible-only E2 mail goes to the wrong set.

  This breaks "eligibility logic is CDC-controlled / Admin is god", and the preview count shown to the admin is wrong in the same way.
- **Reproduction:**
  - `S0S8VerifyTest::test_company_form_data_cannot_override_the_admins_allowed_categories` (FAILS: expected `[1]`, got `[2]`).
  - `S0S8VerifyTest::test_company_form_data_alone_cannot_add_a_category_restriction` (FAILS: expected `[]`, got `[1]`).
- **Suggested fix:**
  - In `AdminPostingController::snapshot()` (and the `JobPosting::eligibilityRules()` fallback), drop `allowedStudentCategories` from the form data, for example `array_diff_key(..., ['allowedStudentCategories' => 1])`.
  - Set the key only from the validated admin input: `$snapshot = $this->snapshot($form); $ids = categoryIds(...); if ($ids) $snapshot['allowedStudentCategories'] = $ids;`.
  - Optionally strip the key from company JNF/INF `form_data` on save.
  - Keep both probes as regression tests.
