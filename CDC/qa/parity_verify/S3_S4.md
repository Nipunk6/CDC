## (b) Findings by severity

No Critical or High findings. Nothing leaks across roles, company data limits hold, and default exports are unchanged from HEAD.

### Medium

**F-1 The placement's "Download as Excel" ignores the enrolled-list filters (S4.4 "of the filtered list").**
- Reproduce: on `/admin/placement-cycles/{id}`, apply a filter such as Placement Status = Placed. The list narrows, but "Download as Excel" still calls `/admin/placement-cycles/{id}/students/export` with no filter query. `AdminPlacementCycleController::exportStudents` and `TemplateExports::cycleStudents` export every enrolment.
- Fix: accept `StudentDirectoryFilters::rules()` on `exportStudents`. With a template (or a new filtered default), apply the filters to `$cycle->enrollments()->whereHas('studentProfile', …)`. Pass `filtersToQuery(filters, {api:true})` in the button's `path`, and record the filters in the `cycle.export` audit. Keep the unfiltered default workbook byte-identical, so the B1 headers stay unchanged.

**F-2 The quick-view drawer does not open from the Progress Grid, Shortlist for Offer, Applicants or Eligible lists (S4.3).**
- Evidence: those lists only `<Link href=/admin/students/{id}>` (pipelinetab.jsx:303, results/page.jsx:159, applicantstab.jsx:113, eligibletab.jsx:121). `StudentQuickView` is only mounted on Students, the stage page and the survey report.
- Fix: mount `<StudentQuickView>` in those components and make the name or roll number open it, keeping the full-page link inside the drawer, as `studentquickview.jsx` already does.

### Low

**F-3 The enrolled-list filters and page are not kept in the URL.**
- Placement page `useState(filters)`; D111(a) records this as a deliberate choice.
- Superset and the master prompt say "Filters are kept in the URL".
- Fix: mirror the Students page, using `useSearchParams` with a prefix such as `ef_`, or a tab-scoped query.

**F-4 The catalogue marks `resume_label` ("Attached Resume") as `company`, but the D78 default company export does not include the resume label.**
- The default puts "Resume Label" inside `if ($admin)`. `current_stage` is also `company` and is new.
- This is latent today because companies cannot use templates (B3).
- Fix: set `resume_label` to `admin` (or record the widening as a decision) before company templates are ever enabled.

**F-5 The template editor can lose the last edit.**
- `useEffect(() => () => clearTimeout(timer.current))` cancels the pending 700 ms autosave on unmount, and there is no `beforeunload` or route guard. Typing a display name and immediately clicking "All Templates" drops the change silently.
- Also, an in-flight save that resolves after a newer edit sets the chip to "All changes saved" while a save is still pending.
- Fix: flush the pending save on unmount or `visibilitychange` (or warn when `state === "dirty"`), and ignore stale save responses with a sequence counter.

**F-6 The admin "Stage Results" template column drops the `[addendum]` marker that the default admin export shows.**
- `ExportFieldCatalogue::stageText`.
- Fix: append ` [addendum]` when `$row->is_addendum && !$companyView`.

**F-7 List avatars are initials only, not photos (S4.2 "photo avatar").**
- D111(a) records this as a deliberate choice for performance.
- Fix, if wanted: lazy-load photos for rows with `has_photo` through `adminBlobUrl`, or accept the deviation as recorded.

**F-8 Search treats `%` and `_` as LIKE wildcards.**
- Reproduce: `GET /api/admin/students?search=%25` returns every student. **Probe P10 fails**, and this is kept as the finding.
- This is pre-existing: HEAD's search had the same `like "%{$search}%"`. S4 extends it to the phone and personal email columns.
- It is not a security issue, since the query is parameterised.
- Fix: escape `\`, `%` and `_` in `StudentDirectoryFilters::apply` and use `like ? escape '\'`.

### Info / cosmetic
- The range inputs read "Greater Than / Less Than", but the bounds are inclusive (≥ / ≤). Consider the labels "At least / At most", or note "inclusive".
- The picker's `noOptionsText` is "No results match" without the query; Superset shows "No results match <query>".
- The Invitation Status radios offer only Invited and Registered, although the API also supports `sent` and `revoked` (S5 scope).
- `AdminResumeController::update` and the bulk verify both re-check `pending` only outside the row lock. This is safe because any decision bumps `updated_at`, so the second decision hits the stale guard (P19).
