## (b) Findings

### MEDIUM

**M1. Re-saving a published survey silently discards answers from forms that are already open.** (probe `test_P26…` FAILS)
- Cause: until the first response arrives, every `PUT /admin/surveys/{id}` that includes `questions` deletes all question rows and creates new ones with new ids (`AdminSurveyController.php:146-153`). The builder sends `questions` on every save while the survey is unlocked, including the Audience tab's "Save" (`F/app/admin/surveys/[id]/page.jsx:317-326`, 692-696). `SurveyAnswerService::validate` ignores answer keys that are not current question ids (`:40-45`).
- Repro: publish a survey with one optional Text question → student opens it (question id 10) → admin changes the deadline and presses Save → student submits `{10: "Dhanbad"}` → **201 "Your response has been submitted."**, stored answers `[]`. With a mandatory question the student instead gets "This question is mandatory" errors keyed by ids the open page does not know, so the error never shows next to a question.
- Fix: keep question rows stable — send `id` from the builder and update rows in place (create/delete only the changed ones), or skip the question sync when the set is unchanged; and in `SurveyAnswerService::validate` reject answers whose keys are not question ids of this survey (422 "This survey changed; reload the page").

**M2. Student Notices page drops older notices on a busy board.** (probe `test_P29…` FAILS)
- Cause: `StudentNoticeController::index` takes the newest 300 published notices of every audience and only then filters by the student's audience (`:23-30`). `StudentSurveyController::index` has the same pattern with 200 (`:30-36`). Each kept row also runs its own audience query (N+1, up to 300 queries per page load).
- Repro: one placement notice from last year + 300 newer notices for Electrical Engineering → a CSE student's Notices page no longer lists their notice (unread count is also wrong).
- Fix: filter in SQL (e.g. resolve the student's matching `notice_audiences` with one query per audience type, or iterate published notices with `lazy()`/chunks until the page is filled) and paginate the filtered list; same for surveys.

### LOW

- **L1. Multipart survey submits lose field errors.** `studentUpload` (`F/lib/studentapi.js:49-72`) throws without `payload`, so `F/app/student/surveys/[id]/page.jsx:72-73` cannot map `errors.answers.{id}` under the questions when a file is attached; only the top message shows. Fix: attach `status`/`payload` to the error as `studentApi` does.
- **L2. Stage page wording differs from Superset.** One "Send Email to Shortlisted / On Hold" button with checkboxes instead of Superset's three buttons "Send Notice to Shortlisted Students" / "Send Email to Shortlisted Students" / "Send Email to Students On Hold" (06 F15). Behaviour is complete; label choice should be recorded or aligned.
- **L3. Attachments vs queued batches.** Notice attachments are deleted on notice delete/replace (`AdminNoticeController.php:98-100,147-149`) even if queued BCC batches still need them (queued mode reads the file at send time, `BroadcastMail::attachments`), so those batches fail. Stage-email files under `stage-emails/` are never cleaned up. Fix: copy the file per send (as stage emails do) or defer deletion until the batch rows are `sent`.
- **L4. Double-submit race.** No DB guard against two simultaneous first submissions when "Allow multiple submission" is off (check-then-insert, `StudentSurveyController.php:70-74`; no unique index). The UI disables the button while busy, so impact is small. Fix: lock the student/survey pair (`lockForUpdate` on a parent row) or a conditional insert.
- **L5. File Upload extension and MIME are checked separately.** `x.png` with PDF content is accepted and served as `application/pdf` named `x.png` (`SurveyAnswerService.php:249-252`). Content MIME is real (finfo) in production, so no injection; cosmetic.
- **L6. Non-responders are not in the Excel.** The export holds responses only; non-responders are on-screen (capped at 2,000). Consider a second sheet.
