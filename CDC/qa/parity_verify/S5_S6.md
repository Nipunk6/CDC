## (b) Findings (by severity)

No Critical or High findings.

### Medium

**F-1. A cancelled (or closed) job profile that was scheduled shows "Scheduled to Open".**
- Where: FE `lib/format.js:84` returns "Scheduled to Open" whenever `is_scheduled` is true, before looking at `status`; BE `JobPosting::isScheduled()` (JobPosting.php:91-94) ignores status, and `summary()` sends it (AdminPostingController.php:896).
- Repro: open a JNF with `scheduled_open_at` = now+1h, then `PATCH /api/admin/postings/{id}/cancel`. `GET /api/admin/postings/{id}` returns `status: "cancelled", is_scheduled: true`. node: `postingStatusLabel({status:"cancelled",is_scheduled:true})` → "Scheduled to Open". Closing a scheduled profile gives the same label. Probe `test_s6_cancelled_scheduled_job_profile_never_opens_or_mails` fails on this assertion. (The scheduler correctly never opens or mails it.)
- Why it matters: the CDC sees a cancelled drive as still about to open, on the list, placement tab, detail header and open card.
- Fix: in `postingStatusLabel`, check `is_scheduled` only when `status === "open"`; or make `isScheduled()` require `status === 'open'`.

### Low

**F-2. E10 "company proposed a shortlist" mails to admins are not tagged with the job profile.**
- Where: `StakeholderNotifier::notifyAdmins` (StakeholderNotifier.php:49-63) calls `mail->send` with no context; caller CompanyPipelineController.php:189.
- Repro: probe `test_s6_every_job_profile_mail_row_carries_job_posting_id` runs E2, E3, E4, stage email, company proposal, E5, applicant list; the only untagged row is `emails.portal-notice | Mailco proposed a shortlist`.
- Impact: missing from that job profile's Communication Log. S6.8 lists E2/E3/E4/E5/E9/S7 explicitly, so this is outside the letter but inside "every job-profile mail".
- Fix: add an optional `$context` to `notifyAdmins` and pass `['job_posting_id' => $jobPosting->id, 'kind' => 'company_proposal']`. The FormEditedByAdminMail sent after editing a floated form (AdminFormReviewController.php:1232) is also untagged.

**F-3. Apply on a hidden (scheduled) job profile answers 422 with a wrong message instead of 404.**
- Where: `StudentApplicationController::isVisible` (:312-317) does not check `released()`/`isScheduled()`; the request then fails `acceptsApplications()` and `closedMessage()` (:296-305) says "This placement is closed, so it no longer accepts applications."
- Repro: probe `test_s6_apply_to_a_scheduled_job_profile_is_404_like_its_detail`: detail 404, apply 422.
- Impact: no application is created (verified), but it confirms that a hidden job profile id exists and gives a misleading reason.
- Fix: add `&& ! $posting->isScheduled()` to `isVisible`, or reuse the `released()` scope.

**F-4. Status labels do not all come from the one helper.**
- `components/student/postingcard.jsx:65` hard-codes Completed / In Process / Closed For Applications. It shows "In Process" for an in_process drive with no stage published (the helper would say "Closed For Applications").
- `app/company/postings/[id]/page.jsx:159` calls `postingStatusLabel(posting.status)` with the bare string, so the in_process/no-stage case always reads "In Process".
- Fix: pass the posting object to the helper in both places (the company and student payloads would need `any_stage_published` / `deadline_passed`).

**F-5. "Resend to all pending" also un-revokes every Revoked student in the filter.**
- Where: AdminStudentInvitationController.php:82-84 (all_pending = everyone not activated); FE `pending = counts.sent + counts.revoked` (invitations/page.jsx:86). The tooltip says "Every Sent or Revoked student", but the confirm dialog does not mention revoked students.
- Impact: an invitation the CDC revoked on purpose (wrong address, left the batch) is silently reissued by a bulk action.
- Fix: limit `all_pending` to `sent`, or say "includes N revoked" in the confirm text. Owner choice; record a decision.

**F-6. Superset's own sample CSV cannot be imported as-is.**
- Where: Superset's template has no Programme/Branch columns. "Current Course Name" (e.g. "B.Tech Computer Science & Engineering") is not mapped (HEADER_ALIASES, StudentAccountService.php:79-99), and programme/branch are required.
- Repro: probe `test_s5_superset_only_columns_are_reported_row_by_row` passes: every row is reported with a programme error, nothing is dropped. Importing a real export from Superset still fails, though.
- Fix (optional): resolve "Current Course Name" through `ProgrammeCatalogue`, or document in the import dialog that Programme and Branch columns must be added. The dialog text only says Superset's sample CSV is accepted.

**F-7. Bulk resend and import send a fresh E1 to suspended students.**
- `resend` skips only activated students (AdminStudentInvitationController.php:90). A suspended, never-activated student gets a new link, but sign-in is still blocked by the `active` middleware. This is a cosmetic or mail-volume issue only.

### Info / operational

- **F-8.** The Communication Log loads every `email_logs` row of the job profile into PHP and groups them in memory (AdminPostingActivityController.php:174-191). It groups by minute, so one BCC broadcast that crosses a minute boundary appears as two rows. This is fine at current scale. Consider SQL `GROUP BY message_ref`.
- **F-9.** A real 6,000-row import runs as one HTTP request (`set_time_limit(0)`, AdminStudentController.php:451). On production, the nginx/php-fpm request timeouts must allow it, or the import should be queued. E1 delivery is already queued per student.
- **F-10.** Scheduled opening needs `schedule:run` cron plus a queue worker in production. This is recorded in the progress file and D112(b).
- **F-11.** `declarationchecklist.tsx` has 3 unused imports (eslint warnings, 0 errors).
